# reflection points (15/09/2026) 

**1. Understanding the project and planning the flow**

I began by understanding what the project required, and then I decided the basic flow of the application. This helped me see that planning first makes the later work easier, because I knew what screen comes first and what comes after it.

**2. Setting up the JavaFX project**

I set up the JavaFX project along with the folders and files it needs. At first this looked like routine work, but I realised that a clean structure matters. When everything is in the right place, I can find my files quickly and avoid confusion later.

**3. Learning the roles of FXML, Java, controllers, and JavaFX components**

I understood what each part does. FXML describes how the screen looks, Java holds the program logic, controllers connect the two, and JavaFX components are the building blocks like labels, images, and buttons. I learned that keeping design and logic separate makes the code easier to read and change.

**4. Creating the basic FXML structure**

I created the basic FXML structure for the app. This was the first time I saw a screen take shape from a text file, and it made the idea of describing an interface in a markup language feel real to me.

**5. Starting the splash screen design**

I started designing the splash screen. Here I had to think about what a user should see in the first moment of opening the app, which made me think more about the user and not only the code.

**6. Adding the basic elements**

I added the app name, logo, version, and a greeting to the splash screen. Each element has a purpose. The name and logo give identity, the version tells the user which release they are using, and the greeting makes the app feel welcoming.

**7. Connecting the splash screen to the main application**

I discussed how the splash screen would connect to the main application. I understood that the splash screen should appear first and then lead smoothly into the main window. I still need to think carefully about how this transition will work in practice.

**8. Initial testing**

I did initial testing to check whether the project structure and the FXML were working. I learned that testing early is useful, because it showed me that my basic setup was correct before I added more features on top of it.
