# reflection points (17/09/2026) 

**1. Completing the splash screen**

I completed the design and the functionality of the splash screen. Earlier it was only a layout, and now it behaves like a real part of the app. I realise that finishing a small part properly gives me a solid base for the rest of the project.

**2. Progress bar and loading messages**

I added a progress bar and loading messages such as "Loading saved notes...". These show the user that the app is working and not frozen. I learned that giving feedback during waiting time makes an app feel more trustworthy.

**3. Last opened time feature**

I implemented a feature that shows when the app was last opened. This taught me that the app needs to remember information between sessions, and not only while it is running.

**4. Close button during loading**

I added a close button that works while the application is loading. At first it seemed like a small detail, but I understood that users should always be able to leave, even during loading. It showed me that good design gives control to the user.

**5. Creating the main screen with FXML**

I created the main application screen using FXML. After building the splash screen, this felt easier, and I could see my understanding of FXML becoming stronger.

**6. Adding the text area**

I added a text area where the user can write notes. This is the core of the app, so I focused on making it simple and comfortable to use.

**7. Saving notes**

I implemented saving notes. This was important for me because it turned the app from a simple screen into something useful. I learned that the app must store the user's work safely, otherwise it has no real value.

**8. Loading saved notes on reopening**

I implemented loading the previously saved notes when the app is opened again. I realised that saving and loading belong together. Saving is only meaningful if the user gets the notes back later.

**9. Unsaved changes warning**

I added detection of unsaved changes and a warning before closing. I understood that this protects the user from losing work by mistake. It made me think about errors a user might make and how my app can prevent them.

**10. Connecting the splash screen to the main screen**

I connected the splash screen with the main screen so that the app moves from one to the other smoothly. Earlier I was unsure how this transition would work, and now I understand how one screen can hand over to the next.

**11. Connecting FXML with the controller**

I connected the FXML components with the Java controller and the application logic. This is where I truly understood how design and logic work together. The FXML shows the screen, and the controller makes it respond to the user.

**12. Layout and appearance**

I worked on the overall layout and appearance of the app. I learned that a clear and neat design makes the app easier to use, and that the look of an app is part of its quality.

**13. Running the app and making corrections**

I ran the application many times to check the complete flow and corrected the problems I found. I realised that testing again and again is a normal part of development. Each run helped me find small mistakes and improve the app step by step.
