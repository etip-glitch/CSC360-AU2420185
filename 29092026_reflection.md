# reflection points (30/09/2026) 

**1. Testing the complete application**

After development, I tested the complete application. I realised that building something is not the same as knowing it works. Testing showed me whether everything I made actually works together.

**2. Checking the splash screen features**

I checked the splash screen, the loading messages, the progress bar, and the last opened time. I wanted to be sure that each small part showed the right thing at the right moment. This taught me that small details are easy to miss unless I check them on purpose.

**3. Testing saving and reopening notes**

I tested saving notes and reopening them. I closed the app and opened it again to confirm that my notes came back correctly. For me, this was the most important test, because the app is only useful if it keeps the user's work safe.

**4. Testing the unsaved changes warning**

I tested the warning that appears when there are unsaved changes. I typed some text, tried to close the app, and checked that the warning appeared. I learned that features meant to prevent mistakes need testing just as much as the main features.

**5. Checking the transition between screens**

I checked the transition from the splash screen to the main screen. I wanted it to feel smooth and not sudden. This showed me that how screens connect is part of the user experience.

**6. Testing the full flow from start to exit**

I tested the complete application flow from start to exit, as a real user would use it. I realised that testing each feature alone is not enough, because problems can appear only when everything runs together.

**7. Starting the PPT**

I started preparing the presentation. This made me step back and look at the project as a whole, not only as code I was writing.

**8. Selecting screenshots and features**

I selected screenshots and the important features to include. I learned that I cannot show everything, so I had to decide what best explains my work. Choosing what to show helped me understand which parts of the project matter most.

**9. Organizing the explanation**

I started organizing the explanation of the project's objective, features, FXML implementation, and working. I found that explaining my project to others is a good way to check my own understanding. If I can explain it clearly, it means I have truly understood it.
